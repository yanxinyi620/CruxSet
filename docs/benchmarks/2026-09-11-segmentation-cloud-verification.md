## 4K 分块推理补测

同日本机使用仓库原图 `tests/fixtures/ritan-spraywall-0822.jpg`（4096×3072），对当前采样修正版 `sam2_tiled` 运行真实 CPU 推理。4 线程、点密度 8、批量 8、IoU .85、稳定度 .90、内部裁剪层 0，缓存模型权重。

- 耗时 91.40 秒，峰值 RSS 2303.40 MiB（约 2.25 GiB）。
- 输出 115 个候选多边形，保留掩码数据 1,810,373 字节。

该结果验证了此参数组合下的本机分块推理内存，不包含 GitHub 排队、环境安装、权重下载或云端传输，也不代表默认点密度 48 的资源需求。

## 验证中修复的问题

- Mask ZIP 经普通 TransformStream 处理后会失去 R2 要求的流长度元数据；改为检查 Content-Length 上限并直接传输原请求流，保持低内存且通过真实 R2 模拟运行时。
- 校准页面拦截全局 fetch 会递归进入共享请求函数；所有请求改为显式 Lab.request，并增加实际执行保存处理器的回归测试。
- 修正云端发布目标默认值、已删除来源任务的校准列表、发布墙面的 pathname 链接和动态页面的静态资源映射。
