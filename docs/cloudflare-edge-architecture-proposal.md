# CruxSet Cloudflare 免费边缘架构提案（历史）

> **历史设计记录，不代表当前实现或部署步骤。** 文中“仅只读”“尚未认证”“不使用 R2”等限制已不再适用。请以 [Cloudflare Edge 部署](cloudflare-edge-deployment.md) 为当前操作说明，以 [设计参考](reference.md) 为运行形态与数据边界的权威说明。

## 1. 目标与选型

使用 **Workers Static Assets + Worker Free + D1 Free**。不开通 R2，不引入 KV、线上文件上传或异步 AI 队列。公开展示图片由管理员在本机处理后，随网站静态资源发布；原图、私有草稿、SAM/YOLO 和图像处理留在本机。

电脑关机后，已发布的墙图、墙与线路浏览继续可用，已迁移的登录、创建/修改/删除线路等业务由 Worker + D1 承担。新增墙图需要管理员本机处理和重新部署；修改线路数据不需要部署。这里的免费目标限定于上述 Cloudflare Free 服务，不包含现有 CloudBase、域名续费、本机电费或第三方 AI 服务。

## 2. 当前仓库边界

```text
当前 Web：浏览器 → Quick Tunnel → Caddy → FastAPI → SQLite + 本地图片
当前小程序：微信 → CloudBase 云函数 → CloudBase 数据库与 Storage
```

Web 当前会随 PC/WSL 关闭而离线；小程序独立运行，本方案不迁移小程序 CloudBase。SQLiteRepository 使用 `documents(collection_name, document_id, body)` JSON 文档表，不是现成的关系表 schema；迁移要显式提取业务字段，不能直接假定已有 users/walls SQL 表。

Web 的 `LocalApiClient` / `ApiSession` 当前依赖全量 bootstrap、墙与线路列表。边缘分页必须同时调整 API 客户端和会话缓存，不能只截断服务端结果。当前登录使用 Argon2 与本地签名 Cookie，云端认证须先完成可行性验证。

## 3. 目标架构

```text
浏览器 → 稳定的 workers.dev 地址
    ├─ 页面、CSS、JS、/wall-images/* → Workers Static Assets
    └─ /api/v1/* → Worker Free → D1 Free

管理员本机
    ├─ FastAPI + SQLite：草稿、墙面创作
    ├─ 分割实验台：AI、人工校准、WebP 生成
    └─ 发布脚本：导出公开内容 → 部署静态资源 → 验证 → 发布墙元数据到 D1
```

仅 `/api/v1/*` 执行 Worker；公开静态图片直接提供，不通过媒体鉴权代理。SPA 回退不能吞掉 API 错误。保持 Workers Free，默认使用 workers.dev，不购买域名；已有域名可另行接入，须验证目标用户实际网络可达性。

Static Assets 是随部署上传的文件集合，不是运行时可写对象存储。不能让普通用户直接上传，也不能将 Worker 发布凭据放在浏览器中。[Static Assets](https://developers.cloudflare.com/workers/static-assets/)

## 4. 数据与能力归属

| 内容或能力 | 权威来源 / 运行位置 | 规则 |
| --- | --- | --- |
| 公开展示图、网页 | Static Assets | 仅明确允许公开的内容，使用内容哈希文件名 |
| 原图、私有墙、草稿、模型 | 本机 | 不进入发布目录或前端构建产物 |
| 已发布墙、Hold、线路、用户与角色 | D1 | 保留业务 ID、编号与归属；线上线路唯一写入源 |
| 墙面创作、识别、校准 | 本机 FastAPI / 实验台 | 完成后发布新的墙；已发布几何仍锁定 |
| 浏览、登录、线路 CRUD、个人资料 | Worker | 服务端验证身份、角色、Wall 与 Hold 引用 |
| 管理员删墙 | Worker + D1 | 有线路时拒绝；静态文件清理另随部署执行 |

沿用 `users`、`walls`、`holds`、`problems`、`admins` 领域语义，不同时改名。Wall 持有归一化 Hold，Problem 引用 Hold ID，可见线路编号由服务端原子生成。

迁移后，本机已发布墙是创作记录，不是线上数据副本的写入权威。后续发布仅新增墙/图片元数据，不能重新导入旧 users/problems 覆盖线上新增内容。旧墙图或岩点变化必须创建新 Wall，不改变已有线路所引用的几何。

## 5. 图片发布与删除

1. 管理员在本机完成识别和人工校准，显式选择要发布的公开墙。
2. 导出器验证至少两个有效 Hold、0–1 坐标、编号/引用完整性，生成 WebP 展示图。沿用最长边不超过 3072px、质量 90 的起点，目测细小岩点清晰度后调整；不通过缩放裁切改变坐标语义。
3. 生成 `wall-images/<sha256>.webp` 与本地发布 manifest。manifest 只含公开墙数据、图片哈希/尺寸和发布 ID，不含密码、邮箱列表、密钥、本机路径或私有草稿。D1 只保存展示图路径，不回退到本机媒体 URL。
4. 静态构建包含本次新增图片及线上仍引用的旧图片。先上传静态资源，再通过线上地址验证图片状态、类型和哈希。
5. 使用独立发布凭据调用管理员发布接口，Worker 检查当前 ASSETS 中的图片并原子、幂等地登记墙/Hold/图片引用。相同发布 ID + 相同内容返回已有结果，不重复分配编号；相同 ID + 不同内容返回冲突。
6. 完成后确认线上墙与图片一致，再报告发布成功。部署或数据库步骤失败须返回明确失败阶段和可重试的发布 ID。

静态资源部署与 D1 无跨服务事务。顺序固定为“图片可用后再发布数据库记录”；失败可能留下尚未引用的公开图片，但不能产生指向缺失图片的新墙。已存在的线上图片必须保留，不能只部署本次新增文件。

公开目录中的文件应视为任何知道地址的人都能读取，哈希地址不是权限措施。因此不能用它保存等待审核的私有图片。删墙先在 D1 标记删除并通过关联线路保护，再在后续资源清理中移除无引用图片；考虑浏览器/CDN 缓存与旧部署版本，不能承诺删除记录后立即撤回所有图片副本。

## 6. API 与前端能力

沿用 `/api/v1` 前缀和现有错误结构。以下为目标接口与范围：

| 接口 | 行为 |
| --- | --- |
| `GET /bootstrap` | 用户、能力开关与首屏摘要，不返回全库数据 |
| `GET /walls`、`GET /walls/:id` | 游标分页公开墙与按需详情/Hold |
| `GET /problems` | 按墙/条件分页，默认 20 条，最多 50 条 |
| `POST /problems`、`PATCH /problems/:id`、`DELETE /problems/:id` | 创建与本人编辑/删除，保留现有编号和权限规则 |
| `/auth/*` | 登录/退出、当前用户、资料；具体认证机制按实施计划的前置验证决定 |
| `DELETE /walls/:id` | 管理员删除无关联线路的墙 |
| `POST /admin/static-wall-publishes` | 本机发布工具专用，验证发布 ID、图片、元数据与权限 |

表内路径均相对 `/api/v1`。云端不提供上传图片、创建草稿、保存岩点、AI jobs 等接口；请求这些能力返回明确的 `CAPABILITY_UNAVAILABLE`，不能依赖隐藏按钮保护。

云端能力标记：`wallAuthoring=false`、`imageUpload=false`、`aiJobs=false`。本地工作台保留这些现有能力。前端线上隐藏上传/标注/识别入口，并说明“新增墙面请在本机工作台处理后发布”；保留公开浏览、线路编辑和个人资料。

认证是启用线上写入前的门槛：先验证现有安全密码参数与免费 Worker 的适配性；不能降低密码强度，也不能让登录回退依赖本机在线。若需改用外部身份提供方，须先确认免费条件、用户可达性与身份映射后再实施；第一阶段只读浏览不受此决策阻塞。

## 7. 免费额度与异常防护

| 服务 | 当前免费条件 | 超限处理 |
| --- | --- | --- |
| Static Assets | 直接静态请求免费且不限量；Free 每版本最多 20,000 个文件，单文件 25 MiB | 文件数或大小超限需减少资源，不能假定继续部署 |
| Worker Free | 每日 100,000 请求，每请求 10 ms CPU | 请求额度耗尽返回错误，不自动按超量收费 |
| D1 Free | 每日 500 万读行、10 万写行；单库 500 MB，账户合计 5 GB | 日读/写耗尽后查询报错；存储满限制新增，不自动按超量收费 |

来源：[静态计费](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)、[Worker 限制](https://developers.cloudflare.com/workers/platform/limits/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)。日额度 UTC 零点重置，即北京时间 08:00。账户其他项目与环境共享相关账户额度。

本方案不创建 R2 订阅、桶或绑定，因此没有新增 R2 账单来源。若账户原已有 R2，是否保留属于独立管理事项，不能从“本项目不用”推断既有订阅已取消。

防护重点变为保持可用性：

- Worker 尽早校验方法、参数大小、游标、身份和权限；API 按 IP 和认证用户分层限流，避免只按 IP 误伤共享网络。
- 起始值：普通查询每用户/匿名 IP 120 次/分钟，登录每 IP 10 次/分钟，写入每用户 20 次/分钟；发布接口仅机器凭据且每凭据 6 次/分钟。返回 429 与 Retry-After。Rate Limiting binding 是按位置、最终一致的近似限流，不作为全局精确计数。[限流语义](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- 登录/注册等敏感浏览器入口按风险使用免费 Turnstile，必须服务端验证 hostname/action/token。机器发布不走验证码。验证码不代替授权。[服务端校验](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- 列表分页、详情按需加载；不再有云端 AI 状态轮询。错误使用有上限的退避，禁止无限自动重试；鉴权响应不进入共享缓存。
- 每日请求或 D1 行额度达到约 80% 告警；D1 单库 400 MB 时暂停非必要新增并清理过期会话/审计。D1 写额度真正耗尽后不能保证还能只读，应提前降级。
- 云端只读维护开关停止写入；提供静态维护说明。静态页面/图片仍可独立提供，但 D1 不可用时不能保证墙列表与线路数据可读。监测不依赖本机，且自身纳入免费预算。

## 8. 迁移与回滚

按“导出与静态验证 → D1 只读浏览 → 认证验证 → 线路写入 → 本机增量发布 → 生产切换”推进，详见[实施方案](superpowers/plans/2026-09-08-cloudflare-static-edge.md)。

首次迁移短暂停止本地线上写入，使用一致 SQLite 快照导出公开墙及关联线路和必要用户；保留 ID、编号、创建时间与作者。身份凭据通过私有迁移渠道处理，绝不放入静态目录。私有墙、草稿和本机媒体路径不导入公开构建。

切换前对数量、哈希、引用与权限做校验并备份。切换后 D1 是线上用户/线路的唯一写入来源，本机不再对同一数据执行无协调双写。

回滚优先回滚兼容的 Worker/前端版本，并保留 D1 最新数据与仍被引用的图片。旧静态版本可能缺少新墙图，不能盲目回滚整个旧部署；应重建包含当前图片集合的兼容代码版本。必须退回 FastAPI 时，先冻结云端写入、导出 D1 最新数据并验证导回，禁止拿旧 SQLite 直接接管。

## 9. 验收标准与非目标

- PC 关闭仍能浏览所有已发布墙图与线路；认证阶段完成后可以登录及进行授权线路写入。
- 发布失败可重试，不重复创建墙/编号，不覆盖线上用户或线路，不丢失旧图片。
- 未授权发布、跨用户线路修改、伪造 Hold/编号和删除有关联线路墙均失败。
- 公开构建不含密码、会话密钥、原图、私有草稿或数据库快照。
- 真实免费 Worker 上验证认证 CPU、分页读行量、编号并发与 429 行为；目标用户实际网络能访问。
- 验证小程序、本机工作台与分割实验台原有发布流程仍可用。
- 不开通 R2，不实现线上图片上传、AI jobs/Agent、KV 或独立消息队列；不迁移 CloudBase；不立即删除 FastAPI。
