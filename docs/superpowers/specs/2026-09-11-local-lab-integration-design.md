# 本地实验台统一入口

已确认方案：一套实验台页面、一套 Python 分割核心，独立 8765 进程；统一从本地 Web 的 /segmentation-lab/ 新标签页进入。暂不增加本地多人账户和实验隔离。

Vite dev 提供现有 static 页面，/api/v1/segmentation-lab/* 优先代理到 8765 的 /api/*，其他 /api 继续连接 8000。页面路由、返回链接、图片、候选、校准、SVG 和发布均走同域。共享构建模块根据 local/cloud 生成配置；默认 web:build 继续输出云端 dist，新增 web:build:local 输出 dist-local，避免本地产物被误部署到 Workers。Vite preview:local 也支持相同本地代理。

本地主站管理员可见实验台入口，描述显示本地图像分割；这只是入口显示规则，不是实验台鉴权。直连 8765 的独立入口及其配置继续可用。模型、实验数据目录和三个发布目标不变，实验台停机不会影响主站 API。开发脚本不再要求仅 CloudBase 发布使用的 URL 才能启动。

cruxset-web 改用本地产物；Caddy 仅在 localhost/127.0.0.1 本机主机名下代理实验台路径，Tunnel 主机名下返回 404，避免将现有免登录实验服务新增暴露到公网。Vite 本地实验路径仅允许本机/私网主机名，主站入口遵循同一条件。长期运行脚本不接管当前 8765 进程，沿用原实验台独立启动方式；日常统一启动仍为 cruxset-dev。

验证：真实 HTTP 代理方法、正文、查询参数及路由优先级；独立页面深链、资源配置、返回地址；本地/云端构建配置和隔离；后端离线及本地入口能力；开发脚本不强依赖 CloudBase；Caddy 配置校验与公共入口拒绝实验路径；现有 TS 与实验台测试。
