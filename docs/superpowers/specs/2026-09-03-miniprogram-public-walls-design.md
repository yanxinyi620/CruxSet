# 小程序公开墙面与线路功能改造设计

## 目标

在不修改或改变现有 Web 页面、FastAPI、SQLite 和分割实验台行为的前提下，将小程序收敛为公开墙面浏览和线路使用端，并增加分割校准结果到 CloudBase 的单向同步能力。

## 范围

小程序保留：

- 浏览公开且可定线的墙面
- 查看墙面线路
- 创建线路
- 查看自己创建的线路
- 编辑自己创建的线路
- 删除自己创建的线路
- 管理员查看和删除墙面

小程序移除普通用户可达的墙面创建、墙面草稿、岩点标注和墙面发布功能。管理员不获得创建或标注能力，只保留墙面查看和删除能力。

## 不可破坏的现有能力

- 不修改现有 Web 页面和 Web API 的路由、请求格式和响应行为。
- 不修改 FastAPI 默认 SQLite 运行方式、本地媒体目录或管理员会话。
- 不修改分割实验台当前发布到本地 FastAPI 的行为。
- CloudBase 或同步器失败时，不回滚、不阻塞、不改变本地 Web 发布结果。

所有新同步代码使用新增模块、配置和云函数旁路接入；现有代码只允许通过新增调用点被动触发，不能改变既有接口语义。

## 架构与数据流

```text
分割实验台校准发布
        ├── 现有路径：本地 FastAPI → SQLite（保持不变）
        └── 新增旁路：同步器 → CloudBase Storage + walls

小程序 → wallManager / saveProblem / deleteProblem / updateProblem 云函数
       → CloudBase
```

CloudBase 是小程序线上数据源。小程序不得直接读写业务集合；所有身份、权限、Wall、Hold 和 Problem 校验在云函数中完成。

## 单向同步设计

新增独立同步器读取已校准结果，生成公开 Wall 发布请求。同步器负责：

1. 校验实验、校准记录、图片和 polygon 数据。
2. 将像素坐标规范化为 0–1 坐标，并生成稳定且连续的 Hold ID、中心点、半径和 `kind`。
3. 上传原始墙图到 CloudBase Storage，使用 `cloud://` 文件 ID 写入 Wall。
4. 写入 `walls`：`visibility: 'public'`、`geometryType: 'polygon'`、公开角度选项和来源元数据。
5. 使用 `publishRequestId` 做幂等控制，重试不会创建重复 Wall。
6. 记录同步成功或失败状态；失败只影响同步结果，不影响本地发布结果。

同步器不得复用或改写现有 FastAPI 的发布接口。图片与 Wall 写入必须具备可重试性；对已上传但尚未写入 Wall 的文件允许后续清理任务回收。

同步写入的 `ownerId` 必须是 CloudBase `users.id`，不能直接使用本地 Web 管理员 ID。同步配置使用服务端密钥，不能进入小程序包。

## 小程序页面与权限

- 线路 Tab：只展示公开、至少包含两个 Hold 的 Wall。
- 创建 Tab：保留“创建线路”和线路草稿/编辑入口，移除“新建墙面”和墙面草稿/标注入口。
- 我的 Tab：保留我的线路列表、线路编辑和删除；“我的墙面”改为管理员权限页面。
- 墙面详情：通过临时 URL 读取 CloudBase Storage 墙图，展示公开线路。
- 管理员墙面页：仅允许查看和删除；有线路引用的墙面不能删除。

## 线路编辑与删除规则

线路创建、编辑和删除都必须由云函数重新读取当前微信身份、User、Problem 和 Wall：

- 编辑和删除仅限 `createdBy` 等于当前业务用户，管理员可按现有规则执行删除。
- 编辑保留 Problem 的 `id` 和 `number`。
- 可编辑名称、描述、角度、难度、脚点规则和 Hold 角色。
- 角度必须属于 Wall 的 `angleOptions`；难度为 V0–V12；描述最多 500 字。
- 至少一个 Start 和一个 Finish；Hold 必须属于对应 Wall，且不能重复分配多个角色。
- 墙面必须仍为公开且可定线状态。

## 云函数边界

保留并收敛现有读取/线路能力：

- `wallManager`：公开墙面、墙面线路、我的线路、问题详情、管理员删除墙面/线路。
- `saveProblem`：创建线路并在事务中生成编号。
- 新增或补齐 `updateProblem`：仅允许创建者编辑并执行完整校验。
- `getWallImageUrl`：继续执行 Wall 归属和公开状态校验。

`adminWall` 的创建墙面、更新墙面和岩点标注动作不再被小程序调用；实现上应禁用或移除这些动作，但不能影响 Web 对应功能。

## 验收标准

1. Web 原有测试和启动方式不变，既有本地发布流程结果不变。
2. 小程序普通用户无法通过导航或直接页面路径进入墙面创建、草稿和岩点标注。
3. 小程序能读取同步后的公开 polygon Wall 和墙图。
4. 用户能创建、查看、编辑和删除自己的线路；他人线路不可编辑或删除。
5. 管理员能查看并删除未被线路引用的 Wall，不能创建或标注 Wall。
6. 同一 `publishRequestId` 重试不会产生重复 Wall；同步失败不会影响本地 SQLite 数据。
7. 小程序在 FastAPI 停止时仍能浏览 CloudBase 数据并完成线路操作。

## 测试策略

- 先为页面路由收缩、线路更新权限、同步数据规范化和幂等行为编写失败测试。
- 运行小程序 TypeScript 检查、云函数单元测试和现有 Web/FastAPI 全量测试。
- 使用 fixture 验证 polygon Wall 可被小程序浏览，草稿/私有 Wall 不出现在浏览列表。
- 使用 CloudBase 验收环境完成：同步公开墙面 → 小程序查看 → 创建线路 → 编辑 → 删除 → 管理员删除墙面。
