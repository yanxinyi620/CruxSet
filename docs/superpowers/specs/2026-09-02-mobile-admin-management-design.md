# 手机端管理员管理中心设计

## 目标

为已登录管理员提供手机优先的管理中心。管理员可查看全部墙面与全部用户，并可删除墙面；用户保持只读。

## 范围

- “我的”页仅对 `isAdmin` 用户显示“管理中心”入口卡片。
- 管理中心包含“墙面”和“用户”两个标签，默认打开墙面。
- 墙面列表展示编号、名称、创建者、公开/草稿状态、创建时间，并提供删除操作。
- 用户列表展示邮箱、用户名、角色、注册时间。未设置用户名时，以邮箱 `@` 前的部分作为显示名。
- 删除墙面前需二次确认，明确关联线路也会被删除。沿用现有服务端级联删除逻辑（关联线路及不再被其他墙面引用的图片）。

不包含：删除用户、修改用户角色、筛选/搜索、分页、墙面编辑。

## 体验设计

遵循既有手机端“我的”页面：浅色背景、圆角彩色入口卡与底部导航。管理员入口作为“我的线路”之后的第四色卡片。

管理中心为独立二级页：顶部返回按钮、标题和简短说明；下方为分段式“墙面 / 用户”标签。每项使用可自适应小屏的卡片，而非横向滚动表格。

## 数据与接口

新增管理员专用用户列表端点，返回用户记录与其认证记录组合出的安全字段：`id`、`email`、`displayName`、`role`、`createdAt`。不返回密码哈希或会话信息。

仓储协议和三种实现均提供用户列表读取能力。服务端用现有 `require_admin` 保护端点：无会话返回 401，非管理员返回 403。用户与认证记录不完整时，服务端跳过无法安全展示的孤立记录。

前端 API 客户端新增获取用户列表的方法。墙面数据和删除继续使用已有管理员权限接口；管理页从当前会话加载的墙面中呈现全量数据。

## 状态与错误处理

- 进入管理中心时加载列表；标签切换不改变路由主页面。
- 删除确认后调用现有删除接口，成功则刷新会话数据并更新当前列表。
- 读取或删除失败时在页面内显示简明错误，保留已有内容并允许重试。
- 空墙面或用户列表显示空状态。

## 验证

- 后端测试：管理员可读取用户列表；普通会话和未登录请求分别被拒绝；返回字段不含敏感认证数据。
- 后端回归：管理员删除墙面仍会级联删除关联线路。
- 前端测试：管理员入口可见性、用户显示名回退与 API 请求行为。
- 运行既有 Web 与服务端测试套件，确保不影响现有登录、墙面和线路流程。
