# 小程序向 Web 对齐设计

## 目标

仅修改微信小程序及其 CloudBase 接口，使小程序中与 Web 共同的浏览、线路、创建和个人线路体验，以现有 Web 页面为唯一功能与视觉基准。`web/` 不做任何功能、页面或设计改动。

## 保持端侧专属的范围

Web 保留登录、注册、墙面上传、自动识别、岩点标注、草稿、我的墙面和管理中心。小程序保留微信登录、TabBar、页面栈、原生 picker、触摸手势和 CloudBase 数据访问。

## 页面与导航

### 公开浏览

公开浏览固定为三层：公开墙面列表、墙面概览、线路浏览。

墙面概览显示墙图、岩点数量和线路数量，只有“浏览线路”动作进入线路浏览。线路浏览默认角度和难度均为“全部”，提供与 Web 等价的角度和难度筛选。移除现有关键词搜索和随机线路。

线路详情为只读，显示线路编号、墙面、角度、难度、脚点规则、角色图例、设定者、说明以及同一筛选上下文中的上一条和下一条。详情页不得提供编辑或删除入口。

### 创建与个人线路

创建路径为“创建 → 选择公开墙面 → 新建线路”。编辑器保持微信原生 picker，但以 Web 的画布优先布局、角色颜色、选中态、操作顺序和保存反馈为视觉与交互基准。

个人线路路径为“我的 → 我的线路”。线路按墙面折叠分组，编辑和删除只在这里提供；公开详情页不承担所有者操作。

### 个人资料

“我的”增加个人资料入口和昵称编辑页。小程序不请求微信昵称授权。首次没有昵称时显示“未设置昵称”，用户手动填写昵称；昵称只保存为 CruxSet `users.displayName`，不修改微信昵称。

## CloudBase 数据边界

`wallManager` 的会话操作返回当前用户的 `displayName`；新增或扩展受身份校验保护的资料更新操作，将校验后的昵称写入当前用户记录并更新 `updatedAt`。

线路详情操作可返回由创建者 `users.displayName` 派生的 `setterName`；若创建者没有昵称，返回“用户”。返回值不得包含 OpenID、UnionID 或其他私密用户字段。

## 视觉语言

小程序共同页面统一采用 Web 的紫色主色、暖色强调、深紫导航、卡片圆角、边框、标签、按钮、错误态和空状态。墙面详情与线路编辑页现有的深绿主题移除。微信原生控件可保持其平台交互方式，但其外围层级、文案和状态应与 Web 对齐。

## 错误与空状态

墙面、线路、昵称读取或保存失败时使用现有小程序错误提示样式与可恢复操作。资料昵称为空、超过长度限制或保存失败时不覆盖已保存昵称。没有符合筛选条件的线路、没有公开墙面、没有个人线路时，采用 Web 对应的文案层级和空状态布局。

## 验收

1. Web 文件没有功能或视觉改动。
2. 小程序公开浏览遵循“墙面列表 → 墙面概览 → 浏览线路 → 只读详情”。
3. 小程序不存在关键词搜索、随机线路、公开详情编辑或公开详情删除。
4. 创建、我的线路、编辑与删除入口符合上述权限边界。
5. 个人资料支持仅在 CruxSet 内使用的手动昵称；CloudBase 不泄露 OpenID。
6. 小程序共同页面采用 Web 的视觉语言。
7. 相关测试、TypeScript 检查与 Web 构建通过。
