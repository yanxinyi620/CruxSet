# CruxSet「我的内容中心」设计

## 目标

将“我的”主页面收敛为一个简洁的内容管理入口，只展示两个入口：我的墙面与我的线路。用户进入对应页面后，再查看和管理具体列表，避免主页面随数据增加而变得冗长。

## 信息架构

```text
我的
├── 我的墙面
│   └── 墙面列表 → Layout 状态、删除 Layout、删除墙面
└── 我的线路
    └── 当前用户创建的线路列表 → 线路详情、删除线路
```

## 我的墙面

“我的墙面”入口显示当前用户拥有的墙面数量和简短说明。进入后显示当前的墙面管理列表：墙面名称、可见范围、Layout 状态，并保留既有的删除 Layout 与删除墙面流程。

删除墙面或 Layout 继续遵循当前业务规则：相关线路会级联删除，操作需要二次确认。

## 我的线路

“我的线路”入口显示当前用户创建的线路数量和简短说明。进入后只显示：

```text
problem.createdBy === currentUserId()
```

线路可以创建在自己的墙面或他人公开墙面上；只要由当前用户创建，就属于“我的线路”。列表按创建时间倒序，单项显示线路编号、名称（若存在）、墙面、Layout、角度和难度。

用户可以打开线路详情，也可以删除自己创建的线路。删除使用确认弹窗；服务端/Mock Repository 仍是最终权限边界，客户端不能据此获得删除他人线路的能力。

## 视觉与交互

“我的”主页面使用与现有三大入口一致的顶部品牌行、大标题和两张清晰卡片。墙面入口采用薄荷绿状态辅助色；线路入口采用浅紫色辅助色。每张卡片具有数量、说明和箭头，不在首页渲染完整数据列表。

“我的墙面”“我的线路”作为独立页面进入 `app.json` 路由，但不加入底部 TabBar。返回时回到“我的”主页面。

## 验证

- 未创建墙面/线路时，两张入口卡显示零数量，但仍可进入各自的空状态页面。
- “我的线路”不显示由其他用户创建的线路。
- Mock 模式与 CloudBase 模式均使用相同的当前用户过滤规则。
- 删除自己的线路后，列表立即刷新；尝试删除他人线路由服务层拒绝。
