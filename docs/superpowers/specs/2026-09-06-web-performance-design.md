# Web 首屏与写操作性能优化设计

## 目标

缩短 Web 在首次打开或登录后的可用时间，并让创建、编辑、删除墙面或线路后的界面更新只读取受影响的数据。优化不引入过期的客户端数据缓存；服务端返回的数据仍是每次访问时的真实状态。

## 当前瓶颈

`ApiSession.refresh()` 并发调用墙面、线路与当前用户三个接口。线路接口在服务端枚举可见线路后，为每条线路单独查询创建者和用户资料，形成 N+1 查询。每次写操作完成后，`ApiSession` 都执行完整刷新，重复下载不受影响的数据。

## 方案

### 初始化快照接口

新增受会话保护的 `GET /api/v1/bootstrap`，一次返回：

- `user`：当前用户；未登录时为 `null`。
- `walls`：按当前会话可见性筛选后的墙面。
- `problems`：仅属于这些墙面的线路，并附带安全的 `setterName`。

该接口复用同一份可见墙面列表，不再分别请求 `/walls`、`/problems`、`/auth/me`。原有接口保留，供兼容和单项调试使用。

### 批量创建者资料查询

服务端将线路中唯一的 `createdBy` 收集为集合。每个用户 ID 最多查询一次对应用户与管理员资料，然后以映射填充线路的 `setterName`。无管理员资料的线路不暴露创建者身份字段。该规则与现有公开响应保持一致。

### 局部会话更新

`ApiSession` 初始化时使用快照接口。写操作成功后仅替换、插入或移除已知的墙面和线路：

- 创建墙面：将返回墙面加入本地集合。
- 更新墙面抓点或发布：以接口返回墙面替换本地墙面。
- 创建、更新线路：以返回线路替换或加入本地线路集合。
- 删除线路或墙面：从本地集合移除对应对象；删除墙面时同步移除其线路。

接口缺少进行局部更新所需对象时，保留一次 `refresh()` 作为可靠回退。失败操作不改变本地会话状态。

## 可观测性

Web API 客户端会在开发环境输出每个请求的耗时、方法和路径；不会记录请求体、Cookie 或其他敏感数据。这样可在浏览器控制台确认优化前后的首次加载与写操作耗时。

## 错误处理与兼容性

初始化接口任一失败时，客户端保持现有错误路径。未登录访问仍可获得公开墙面与线路，`user` 为 `null`。页面继续通过 `ApiSession` 获取墙面和线路，无需改动路由或渲染代码。

## 验收标准

- 首次会话刷新只产生一个初始化 API 请求。
- 初始化响应内的每个创建者 ID 最多查询一次用户资料和一次管理员资料。
- 写操作成功后不触发全量 `refresh()`。
- 删除墙面后，本地会话不再保留该墙面或其线路。
- 现有 Web 与服务端测试继续通过，并增加覆盖初始化快照、批量资料查询和局部更新的测试。
