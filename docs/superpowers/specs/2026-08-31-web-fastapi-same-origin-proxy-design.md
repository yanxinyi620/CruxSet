# Web FastAPI 同源代理设计

## 目标

让手机只访问电脑局域网内的 Web 服务（`:5173`），由 Web 开发服务器在电脑本机转发 API 与媒体请求至仅监听 `127.0.0.1:8000` 的 FastAPI。

## 架构

浏览器中的 `LocalApiClient` 使用同源相对地址作为 API 基地址，因此页面从 `http://192.168.x.x:5173` 打开时，请求仍发送到该 Web 服务的 `/api/...` 路径。Vite 开发服务器将 `/api` 代理给 `http://127.0.0.1:8000`，并保留路径与 Cookie。FastAPI 不再需要暴露局域网端口。

媒体上传接口返回的 `/api/v1/media/...` 同样属于 `/api` 前缀，自动通过同一代理访问，不需要为图片增加第二套地址规则。

## 行为与兼容性

- `localApiBaseUrl()` 默认返回空字符串，所有现有 API 调用继续通过 `${baseUrl}/api/...` 形成同源请求。
- 允许调用方显式传入完整 API 地址，维持现有单元测试和直接 API 调试能力。
- Vite 配置只在开发服务时启用代理；生产部署应由反向代理提供等价的 `/api` 转发规则。
- FastAPI 保持 `127.0.0.1:8000` 监听；本地 HTTP 登录仍须用 `SESSION_COOKIE_SECURE=false` 启动以让浏览器发送会话 Cookie。

## 验证

- 单元测试断言 LAN 页面默认 API 基地址为同源，而不是 `LAN_IP:8000`。
- 配置测试断言 Vite 的 `/api` 代理指向 `127.0.0.1:8000` 且开启 `changeOrigin`。
- 在 FastAPI 仅监听 loopback 时，从局域网 Web 地址登录并加载墙面及媒体。
