# 小程序同步 Web 功能：差异与改造计划（已确认并实施）

**状态：** 用户已确认范围。开发、自动化回归及微信模板/样式编译已完成；CloudBase 部署联调和 Android/iPhone 真机验收尚未执行。下方差异表保留实施前基线，交付结果见 `2026-09-11-miniprogram-web-parity-delivery.md`。

**基线：** 2026-09-11，提交 `41700a0`。对比当前小程序页面、CloudBase 云函数、共用 Web 前端、FastAPI 与 Cloudflare Worker 的实际代码。未进行线上页面、CloudBase 控制台或真机验证；部署版本是否与仓库一致属于实施前核验项。

**目标：** 小程序同步本机与云端 Web 除实验台之外的主要功能，保持微信原生交互与独立 CloudBase 数据。

## 1. 对比结论

本机和云端使用相同的 `web/src/main.ts` 页面，但能力仍受后端配置控制，例如云端上传依赖 MEDIA。以两端正常配置下的共同业务行为为目标，不把每一项后端实现视为完全相同。

| 功能 | Web 当前行为 | 小程序当前行为 | 拟改造 |
| --- | --- | --- | --- |
| 导航 | 线路、创建、我的；二级功能页 | 同样三个主入口 | 保留结构，补充权限对应入口 |
| 公开浏览 | 无需登录浏览墙面与线路 | 页面查询经 wallManager 身份校验，启动时自动微信登录 | 保留微信身份；修复初始化与查询并发、登录失败重试，不复制邮箱登录页 |
| 墙面与线路筛选 | 墙面概览、角度/难度筛选 | 已具备 | 保留并回归，确保大列表完整加载 |
| 线路连续浏览 | 沿用当前筛选结果前后切换，支持全屏预览 | 前后切换重新按当前线路角度和难度查询；无对应全屏入口 | 传递筛选上下文，补全屏，返回保留筛选和位置 |
| 线路编辑 | 五种角色、脚点规则、撤销、清空、名称说明、保存与草稿 | 主体已具备；草稿仅保存角度、难度、脚点规则和岩点 | 补名称、说明、选中角色恢复及离开处理，保留编号和所有权规则 |
| 我的线路 | 按墙面分组、编辑、删除 | 已具备 | 刷新后保持展开状态；一致的加载、空、错误状态 |
| 个人资料 | 名称、邮箱、退出；注册登录 | 微信身份及手动昵称 | 保留微信身份与昵称，不新增邮箱密码或跨端绑定 |
| 创建墙面 | 管理员上传图片并创建私有草稿 | 创建入口只有新建线路；旧墙面页面未注册且已停用 | 新建管理员墙面创作流程 |
| 标注与发布 | 轻量自动识别、手动增删移动、撤销/恢复、清空、保存草稿、公开发布锁定 | 没有可用页面及完整写入接口；仅有基础 WallEditor 领域类 | 新建页面、画布交互、云函数与发布锁定校验 |
| 我的墙面 | 用户管理自己的墙面；删除关联线路和无引用图片 | 页面仅管理员可进，实际列全站墙面；listMyWalls 服务存在但未接入 | 自有墙面与全站管理分开，普通用户可管理自己已有墙面 |
| 墙面删除 | 自有墙面级联清理，管理员另有全站删除入口 | 仅管理员可删，有线路即 WALL_IN_USE；已有无引用图片清理 | 对齐级联删除，补并发保护、失败恢复和明确确认提示 |
| 管理中心 | 全站墙面和用户列表；用户实验台授权 | 只有管理员墙面列表，无用户页 | 新增墙面/用户两页；不包含实验台授权、额度 |
| 图片与画布 | Web 有图片缓存与全屏预览等机制 | Canvas 已支持拖动、缩放和实例内图片复用 | 补跨页面图片缓存、地址过期恢复、切墙异步结果隔离与绘制性能 |
| 跨平台发布 | 实验台提交与审核申请，向目标平台发布 | 接收 CloudBase 发布结果 | 保留接收链路，不搬迁申请审核界面 |

## 2. 范围建议与选择

推荐 **原生小程序补齐主要业务功能**：继续使用 CloudBase，将 Web 的业务规则落实到原生页面和云函数。维护成本主要在墙面编辑与服务端生命周期，但与当前工程结构和微信交互一致。

其他选择：只补浏览与管理成本较小，但不满足墙面创作的主要功能同步；以 Web 页面承载功能可减少部分页面重复开发，但会引入域名、登录与数据连接边界，不能自然复用当前 CloudBase 身份。本轮不推荐后两种。

建议确认以下边界：

1. 纳入管理员“上传墙图 → 私有草稿 → 手动标注 → 发布”完整流程；普通用户仍只创建线路，不因本次改造获得墙面创建权限。
2. 普通墙面编辑器的轻量自动识别属于本轮范围，安排在手动闭环完成之后。它是 `web/src/auto-detect.ts` 的像素启发式处理，不是实验台模型任务。
3. 排除分割实验台页面、AI 模型任务、实验档案、校准工作流、实验台授权与额度、跨平台申请及审核 UI。继续兼容实验台发布到 CloudBase 的墙面。
4. 保留微信登录，不同步 Web 邮箱密码，不自动同步三端账户、墙面和线路，不新增普通用户墙面归属迁移。
5. 管理员用户列表只展示 CloudBase 内部用户 ID、昵称、身份与创建时间等必要字段；不虚构邮箱，不向客户端暴露 OpenID/UnionID，不新增 Web 也没有的封禁或管理员任命操作。

## 3. 分阶段改造计划

### P0：确定权限与数据契约

涉及：`wechat/miniprogram/services/{cloud,users,walls,problems}.ts`、`wechat/cloudfunctions/wallManager/index.js`、`config/cloudbase.*.json`、相关契约测试。

- [x] 统一当前用户、管理员、墙面归属、公开/私有与发布锁定判定，页面隐藏和云函数校验同时执行。
- [x] 为启动身份初始化提供可等待的统一入口，失败后允许重试，覆盖冷启动与分享直达。
- [x] 列表采用明确的分批加载契约，覆盖墙面、线路和用户；查询条件白名单化，用户资料按必要字段投影。
- [x] 定义墙面创建、保存岩点、发布、删除预检、用户列表接口；复用现有 Wall、Hold、Problem 结构和稳定编号规则。
- [x] 明确私有上传的授权、文件归属和短期图片访问流程，保持业务集合与私有图片不可由客户端随意读写。

验收：普通用户不能调用管理员动作；不同用户私有墙面不可互访；超过单批数量的数据不漏项；首次启动不因身份尚未初始化而误报无权限。

### P1：补齐现有浏览与线路体验

涉及：`pages/route-browser/`、`pages/problem/detail/`、`pages/problem/editor/`、`pages/me/problems/`、`components/wall-canvas/`；新增小程序浏览上下文与图片缓存辅助模块。

- [x] 详情页沿用列表筛选条件及有序结果，前后切换不额外缩小角度/难度；分享直达采用明确的全墙默认上下文。
- [x] 新增线路全屏预览与关闭，保留角色轮廓、脚点规则、拖动和缩放；返回列表恢复筛选与位置。
- [x] 草稿覆盖名称、说明、当前角色和线路参数；以用户和新建/编辑对象隔离；保存成功才清理，失败保留。
- [x] 我的线路在编辑、删除后刷新数据并保留仍有效的分组展开状态。
- [x] 图片缓存按文件标识管理，临时地址过期可重新获取；切换墙面时忽略旧异步结果，修正跨手势缩放边界并控制重绘频率。

验收：从“全部”筛选进入后可跨角度/难度切换；筛选结果边界正确；名称说明中途离开后可恢复；保存失败无内容丢失；分享冷启动可进入详情。

### P2：我的墙面与管理中心

涉及：`pages/me/`、`pages/me/walls/`；新增 `pages/admin/management/` 页面；扩展 `services/users.ts`、`wallManager` 与权限/删除测试。

- [x] “我的墙面”仅列当前用户拥有的内容，对普通用户开放，即使没有墙面也显示清楚的空态。
- [x] 管理员进入独立管理中心，墙面页显示稳定编号、名称、公开/草稿状态、创建者、时间和删除入口；用户页展示必要资料。
- [x] 删除前展示关联线路数量和不可恢复后果；实现墙面、关联线路、无引用原图/展示图的清理。
- [x] 对大批关联数据采用分批、可重试的删除流程；删除期间阻止新增关联线路，防止形成孤立数据；失败时提供可恢复状态。
- [x] 保留仍被其他墙面引用的图片；媒体删除失败记录待重试任务；检查 segmentationPublishes 回执与被删墙面的处理，避免重试误报已发布或意外恢复内容。

验收：普通用户仅能删除自己墙面；管理员全站管理独立；含其他用户线路的自有墙面按确认后的规则一并删除；共享图片不误删，失败重试不会重复破坏数据。

### P3：管理员墙面创作与手动标注

涉及：`pages/create/index.*`、恢复并重写 `pages/admin/index.*`、`pages/create/drafts/index.*`、`pages/admin/wall-editor/index.*`、`app.json`；新增墙面标注画布；`domain/wall-editor.ts`、`services/walls.ts`；实现 `wechat/cloudfunctions/adminWall/` 的认证业务接口。

- [x] 管理员创建页新增“新建墙面”和“标注岩点”；相册/拍照后填写名称、上传图片、创建私有草稿。
- [x] 新的管理员上传流程使用微信身份鉴权，不将实验台签名密钥放到小程序；处理文件类型、大小、尺寸和失败后的孤立文件清理。
- [x] 草稿列表可继续编辑；标注支持查看、添加、移动、删除、撤销、恢复、清空及草稿保存。
- [x] 统一圆形与 polygon 岩点编辑语义：移动/调整不能留下过时轮廓，归一化坐标与图片方向一致。
- [x] 发布至少需要两个合法岩点，提交成功后公开并锁定；云端拒绝对已发布几何的修改，重复提交不重复建墙或占用编号。
- [x] 发布完成即可在浏览和新建线路选择器使用该墙面。

验收：管理员从手机上传到发布再创建线路形成完整闭环；普通用户越权失败；私有草稿不可公开访问；重新进入能恢复保存内容；已发布墙面不能继续改岩点。

### P4：普通编辑器轻量自动识别

涉及：`web/src/auto-detect.ts` 的纯像素算法、小程序内算法模块、`pages/admin/wall-editor/` 与标注画布。

- [x] 将无 DOM 的算法与小程序图片像素读取适配分开；优先保持 Web 页面和行为不变，不让小程序运行时依赖 Web 目录。
- [x] 对图片降采样后识别，明确正在处理、取消/过期结果、识别为空、失败状态。
- [x] 自动结果进入同一手动编辑和历史记录流程；遵循 Web 对旧标注的替换行为与发布校验。

验收：固定图片在一致算法参数下得到一致的规范化结果；中端真机运行不卡死，结果可人工修正、保存和发布。不接入任何实验台模型或任务队列。

## 4. 执行与验收边界

确认后按 P0 → P1 → P2 → P3 → P4 → P5 推进，每阶段形成可独立审阅的变更。P3 是最大工作量，不能只恢复旧按钮；P2 的删除属于业务规则变更，必须与服务端及现有测试一同修改。

本提案不预先承诺具体工期；真机画布性能、CloudBase 现有部署版本、历史编号与删除回执数据需要在实施时验证。当前仅对代码存在的功能作出结论，不将历史设计文档或未运行的测试视为上线证据。

**已确认范围：采用原生对齐方案，纳入管理员墙面创作、级联删除和轻量自动识别，排除实验台及跨端账号/数据自动同步。**
